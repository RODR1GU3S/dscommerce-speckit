## Disciplina de testes e evidências

Escrever os testes antes da lógica correspondente. Quando uma API Java nova for indispensável à compilação, escrever primeiro o teste e prover somente a assinatura/estrutura mínima nos arquivos de destino indicados, sem implementar regras, mapeamento JPA, handlers ou endpoint. Essa preparação não comprova RED. Só registrar RED após executar um teste compilável e preparado que falhe por comportamento ausente/incorreto, por exemplo HTTP 404 em vez de 201, cálculo incorreto ou assertiva de schema ausente em INFORMATION_SCHEMA. Erro SQL na preparação, bean ausente no startup, compilação quebrada e fixture recusada não são provas.

Scaffolding deve compilar e permitir inicializar o contexto existente: métodos de classes concretas precisam de corpos provisórios sem a lógica alvo; serviços provisórios não recebem @Service/@Component nem registro por @Bean, e tipos de domínio provisórios não recebem @Entity. Não alterar a configuração de scan para mascarar erro de preparação; só contar RED quando compilação/startup/fixtures permitirem alcançar a assertiva comportamental.

Os testes HTTP iniciais podem usar contexto existente, JSON bruto e JDBC sem importar classes novas; o T011 deve chegar à assertiva de 201 antes da implementação. T013 deve conferir metadados antes de tentar inserir nas tabelas ainda ausentes.
